## 一、Go 后端 BidService.Accept() 分析

### 已实现功能

| 功能 | 状态 | 说明 |
|------|------|------|
| Bid 状态更新 | ✅ | status=2, accepted_at 写入 |
| Project 状态变更 | ✅ | status=3, provider_id, bid_id, agreed_price, matched_at |
| 需求方通知 | ✅ | "撮合成功" + 对方联系电话 |
| 造物者通知 | ✅ | "恭喜被选定" + 需求方联系电话 |
| IM 会话创建 | ✅ | 自动建立/更新私聊会话，绑定 project_id |
| 系统消息 | ✅ | "撮合成功！你们已经可以开始沟通了" |
| 待支付订单 | ✅ | createPendingProjectOrderWithRepos() |
| 支付通知 | ✅ | NotifyPayerPendingOrder() |
| 事务一致性 | ✅ | 所有写操作在同一 gorm.DB.Transaction 内 |

### 缺失项（需 Go 团队补充）

| 缺失项 | 优先级 | 说明 |
|--------|--------|------|
| `agreed_days` 未写入 | 🔴 高 | Accept() 中 UpdateFields 没有写 `agreed_days`（即 bid.EstimatedDays），AI PM 生成依赖此字段 |
| AI Agent on-matched 回调 | 🔴 高 | Accept() 事务提交后应异步调用 `POST /api/v2/lifecycle/on-matched`，触发 PM 方案自动生成 |

**建议 Go 端改动**（Accept() 末尾追加）:

```go
// 1. 补充 agreed_days 写入（在事务内 UpdateFields 中加一行）
"agreed_days": bid.EstimatedDays,

// 2. 事务提交后异步触发 AI PM 生成
go s.callAIOnMatched(project.UUID, providerID, bid.ID, bid.Price, bid.EstimatedDays)
```

## 二、AI Agent 落库（数据库持久化）状态

### 持久化架构

```
请求 → SessionManager → Redis (缓存, TTL 24h)
                      → MySQL ai_project_stages (持久)
                      → MySQL ai_documents (持久)
```

读取路径: Redis 优先 → MySQL 兜底 → 回填 Redis

### 各接口落库情况

| 接口 | 路由 | Redis | MySQL | 说明 |
|------|------|-------|-------|------|
| 初始化流水线 | POST /api/v2/pipeline/{id}/init | ✅ | ✅ | 创建 ProjectState，4 个阶段全部初始化为 pending |
| 需求分析-开始 | POST /api/v2/requirement/{id}/start | ✅ | ✅ | requirement 阶段 → in_progress |
| 需求分析-流式 | POST /api/v2/requirement/{id}/start/stream | ✅ | ✅ | 同上，SSE 流式返回 |
| 需求分析-确认 | POST /api/v2/requirement/{id}/confirm | ✅ | ✅ | requirement → confirmed |
| 设计方案-开始 | POST /api/v2/design/{id}/start | ✅ | ✅ | design → in_progress |
| 设计方案-确认 | POST /api/v2/design/{id}/confirm | ✅ | ✅ | design → confirmed |
| 任务拆解-开始 | POST /api/v2/task/{id}/start | ✅ | ✅ | task → in_progress |
| 任务拆解-确认 | POST /api/v2/task/{id}/confirm | ✅ | ✅ | task → confirmed，流水线完成 |
| PM 方案-查看 | GET /api/v2/pm/{id}/document | - | ✅ 读 | 只读，从 ai_documents 取 |
| PM 方案-重生成 | POST /api/v2/pm/{id}/regenerate | ✅ | ✅ | 重新生成 PM 文档 |
| 生命周期-撮合成功 | POST /api/v2/lifecycle/on-matched | ✅ | ✅ | 自动生成 PM + 标记 confirmed |
| 智能撮合 | POST /api/v2/match/recommend | ❌ | ❌ | 纯计算，不落库 |
| 对话助手 | POST /api/v2/chat/send | ❌ | ✅ | 对话历史存 ai_conversation_messages |
| 团队评级 | POST /api/v2/rating/evaluate | ❌ | ✅ | 评级结果存 ai_provider_profiles + ai_vibe_power_logs |

### MySQL 表结构（AI Agent 专属，ai_ 前缀）

| 表名 | 用途 |
|------|------|
| ai_project_stages | 流水线阶段状态 (project_id, stage, status, version) |
| ai_documents | 生成的文档内容 (project_id, stage, content, version) |
| ai_conversation_messages | 对话历史 |
| ai_provider_profiles | 团队方评级档案 |
| ai_vibe_power_logs | VibePower 评分变更日志 |

## 四、撮合成功后通知 + 状态变更机制

### 完整流程（Go + AI 协同）

```
发起人点击「选定」
    ↓
Go BidService.Accept()  ← 事务内
    ├─ bid.status = 2 (已接受)
    ├─ project.status = 3 (已撮合)
    ├─ project.provider_id = 造物者ID
    ├─ project.agreed_price = 商定价格
    ├─ 通知需求方: "撮合成功 + 对方电话"
    ├─ 通知造物者: "恭喜被选定 + 需求方电话"
    ├─ 创建/更新 IM 会话
    ├─ 发送系统消息: "撮合成功！你们可以开始沟通了"
    └─ 创建待支付订单 + 支付通知
    ↓
Go 异步调用 (TODO: 待实现)
    ↓
AI POST /api/v2/lifecycle/on-matched
    ├─ 加载 requirement.md + design.md + task.md
    ├─ 注入 agreed_price + agreed_days
    ├─ PM Agent 生成 project-plan.md
    ├─ 标记 pm 阶段 confirmed
    └─ 返回结构化里程碑数据 → Go 可存入 milestones 表
```
